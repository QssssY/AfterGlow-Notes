设计稿指定正文用 Noto Sans SC。这五个字说出来轻巧，落地时是一道体积题：**中文字体一个字重就有一万多个字形，文件 1.1MB 起步**，四个字重原样上线就是四五兆——比整个站的其余部分加起来还重。

英文站的"字体自托管最佳实践"到中文这里全部失效，得换一套思路。

## 现成的分片方案，账算不过来

Google Fonts（以及镜像它的 fontsource）对 CJK 的处理是**切片**：把整套字体按使用频率切成 100 多个小 woff2，配 100 多条带 `unicode-range` 的 `@font-face`，浏览器按页面用到的字按需下载。

听起来很美，直到算 CSS 的账：101 条 `@font-face` × 4 个字重的样式表，原始体积 514KB。样式表是**渲染阻塞资源**，这比字体本身更伤首屏。字体分片可以懒加载，声明它们的 CSS 可不行。

## 换个问法：这个站到底用了多少个字

博客不是用户生成内容的平台，**全站会出现哪些汉字，构建的时候就已经确定了**——都在 Markdown 文章、JSON 数据和组件文案里躺着。那就没必要为一万个字形买单：

1. 构建前扫一遍 `src/`，正则把所有 CJK 字符捞出来去重（几百个字）；
2. 用 [subset-font](https://github.com/papandreou/subset-font) 从完整字体里只抽这些字形，输出 woff2；
3. 生成一条对应的 `@font-face`，`unicode-range` 限定 CJK 区段，拉丁字符照旧走 fontsource 的 13KB 小文件。

这个站的 `scripts/subset-cjk.mjs` 干的就是这件事，挂在 `dev` 和 `build` 前面自动跑。438 个用字时，一个字重 57KB——**从 1.1MB 到 57KB，砍掉 95%**。新文章带来生僻字也不怕，下次构建自动进子集。

```js title="scripts/subset-cjk.mjs（节选）"
const subset = await subsetFont(fullFont, [...usedChars].join(''), {
  targetFormat: 'woff2',
})
```

## 顺手薅到的两个附加优化

**砍掉整个字重**。设计稿用了 400/500/600/700 四档，但检查后发现 600 只出现在移动端 Tab 激活标签一处。删掉它，CSS 字重匹配规则会自动落到 700，小字号下肉眼无差——白省四分之一体积。子集化的体积是"字符数 × 字重数"，砍字重比砍字符狠多了。

**关键字重 preload**。子集再小，不提前拉也会有一瞬间的后备字体闪烁（FOUT）。把首屏必用的 400 字重加进 `<link rel="preload" as="font">`，让它和 CSS 并行下载，正文出现时字体已就位。

## 一条注意事项

子集文件属于构建产物，**别提交进仓库**（这个站把 `src/generated/` 整个 gitignore 了）。它由源码内容派生，提交它等于把同一份信息存两遍，还会在每次改文案时污染 diff。

> 中文 Web 排版的困境从来不是没有好字体，而是好字体太重。子集化是目前唯一能把"自托管 + 全定制 + 不到 100KB"三件事同时拿到手的路。
